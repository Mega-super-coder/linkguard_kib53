# LinkGuard, команда KIB-53

## 1. Проблема и пользователь

В маркетинговой студии (5–30 человек) ссылки на корпоративные документы рассылаются клиентам и подрядчикам,
и контроль над ними теряется: конфиденциальные файлы остаются доступны по публичным ссылкам, права на редактирование
выдаются внешним пользователям без срока действия. Это создаёт риск утечки данных и нарушения обязательств перед
клиентами. Пользователь прототипа — руководитель проектов / ответственный за ИБ в студии.

**Цель MVP:** по загруженному локальному реестру документов выявить нарушения правил доступа, оценить их по уровню
риска и получить отчёт с рекомендациями по исправлению.

## 2. Как запустить (ничего устанавливать не нужно)

1. Откройте сайт: https://<ваш-логин>.github.io/linkguard_kib53/
2. Нажмите «Запустить на демо-данных» — или перетащите файл `test_data.csv` (или любой свой `.csv` / `.json`).
3. Изучите дашборд и таблицу нарушений, отфильтруйте по уровню риска.
4. Скачайте итоговый отчёт кнопкой «⬇️ Скачать отчёт (CSV)».

Приложение работает **без сервера и учётной записи**, полностью в браузере. Данные никуда не отправляются,
проверяемые ссылки не открываются, права доступа не изменяются.

Расширенная версия (Python + Streamlit) для запуска на локальной машине — в папке `streamlit/`:
`pip install -r requirements.txt && streamlit run app.py`.

## 3. Выполненные функции

- Загрузка реестра документов в формате `.csv` (разделители `;` и `,`, кодировка UTF-8) или `.json` (массив или `{"rows": [...]}`).
- Движок правил R1–R4 с уровнями риска (Критический / Высокий / Средний) и рекомендациями.
- Дашборд: число проверенных документов и распределение нарушений по уровням риска.
- Таблица нарушений с фильтрацией по уровню риска.
- Экспорт отчёта в CSV (UTF-8 с BOM, открывается в Excel).
- Обработка ошибок: неверный формат файла, отсутствие обязательных колонок, пустые/нераспознанные значения — приложение не падает, выводит понятное сообщение и предупреждения по строкам.

## 4. Движок правил

| Правило | Условие | Риск | Рекомендация |
|---|---|---|---|
| R1 | `access_type = Публичный` и конфиденциальность «Конфиденциальный»/«Строго конфиденциальный» | Критический | Сменить тип доступа на «Внутренний», отозвать публичную ссылку |
| R2 | `permissions = Редактирование` и доступ «Публичный»/«Внешний» | Высокий | Снизить права до «Просмотр» |
| R3 | `access_type = Внешний` и нет срока действия ссылки | Средний | Установить срок действия ссылки (7–30 дней) |
| R4 | Проект «Завершен», доступ не «Внутренний» | Средний | Отозвать ссылку / перевести документ в архив |

## 5. Воспроизводимое демо и тестирование

Нажмите «Запустить на демо-данных»: ожидается **4 нарушения** (R1, R2, R3, R4 — по одному).

Файл `test_data.csv` (10 синтетических документов) — ожидается **7 нарушений**: R1×2, R2×2, R3×2, R4×1 и 3 безопасные строки.

Проверки граничных ситуаций (QA-протокол, Оськин М.А., Security/QA):

| № | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Битый CSV / картинка вместо файла | Понятное сообщение об ошибке, приложение работает | пройдено |
| 2 | CSV без обязательных колонок | Перечисление недостающих колонок | пройдено |
| 3 | PNG вместо CSV/JSON | «Неподдерживаемый формат файла» | пройдено |
| 4 | JSON-массив и `{"rows": [...]}` | Обе формы загружаются | пройдено |
| 5 | Разделитель `;` и BOM (сохранение из Excel) | Корректный парсинг | пройдено |
| 6 | NaN в confidentiality/access_type | Предупреждение, строка пропущена в затронутых проверках | пройдено |
| 7 | Мусор в has_expiration («???») | Предупреждение, Правило 3 не применяется | пройдено |
| 8 | `has_expiration`: Да/Нет, True/False, 1/0 | Все варианты распознаются | пройдено |

## 6. Безопасность и ограничения

Клиентское автономное приложение не запрашивает персональные данные, не делает сетевых запросов и не взаимодействует
с реальными информационными системами. Все данные — синтетические. Правила аудита статичны; конфигурируемые правила,
PDF-отчёт и учёт «осиротевших» ссылок — план развития.
